# YAS modernization — first implementation slice

This isolated Go workspace preserves the PHP source at `/Users/dany/Projects/work/YAS-SOKA-ISHIKISTAA-MEGAPROMO`. It is **not production-ready**. The existing application and databases have not been changed.

Implemented: JSON callback parsing for Soka, Ishikistaa, and MegaPromo; matching callback routes and success response shape; MySQL transaction for callback receipt and outbox intent; RabbitMQ relay with publisher confirms, retry, lease, and dead-letter state; health/readiness endpoints; unit and HTTP contract tests, including PHP-derived payment routing characterization. The target domain schema now covers subscriptions, activation, questions, interactions, payments, answers, points, promotions, prizes, outbound messages, and processing deduplication. The relay publishes to **new** queues. Dedicated Soka MO and point-purchase payment consumers now handle the database side of one purchase path; other product paths and SMS delivery remain pending.

## Local commands

Use Go 1.24+ and dependencies from `go.mod`. `go run ./cmd/migrator` prints an offline migration plan without connecting to a database. For an empty, isolated MySQL 8.0+ development database, set `MIGRATION_DB_DSN` and run `go run ./cmd/migrator -apply -expected-db <exact_database_name>` after review. The command checks the target name, takes a database lock, records checksums and status, and refuses to continue after a partial failure. MySQL DDL cannot be rolled back as a transaction; inspect and repair a failed migration manually. Set `MYSQL_DSN` and start the API with `go run ./cmd/callbacks`. Set `AMQP_URL` and start `go run ./cmd/outbox-relay`. Run `go run ./cmd/soka-mo-worker` and `go run ./cmd/soka-point-worker` with `MYSQL_DSN` and `AMQP_URL` for the isolated purchase workers. Never commit environment values.

`go test ./...` and `go test -race ./...` exercise the code without a database. The Go migration command applied both scripts and synthetic smoke data in a disposable MySQL 8.4 container; a second run skipped applied scripts, and a mismatched database name was rejected. Invalid cross-product references, missing parents, negative payment amounts, and duplicate point awards were rejected. The callback, Soka MO, and Soka point-purchase MySQL integration tests passed in disposable isolated MySQL 8.4 databases, covering replay, amount validation, failure outcomes, and rollback. These tests skip during ordinary `go test` unless `TEST_MYSQL_DSN` selects a `yas_test_` database. RabbitMQ application integration tests, provider contract fixtures, load tests, restore tests, and cutover rehearsal are pending.
