# YAS modernization — first implementation slice

This isolated Go workspace preserves the PHP source at `/Users/dany/Projects/work/YAS-SOKA-ISHIKISTAA-MEGAPROMO`. It is **not production-ready**. The existing application and databases have not been changed.

Implemented: JSON callback parsing for Soka, Ishikistaa, and MegaPromo; matching callback routes and success response shape; MySQL transaction for callback receipt and outbox intent; RabbitMQ relay with publisher confirms, retry, lease, and dead-letter state; health/readiness endpoints; unit and HTTP contract tests, including PHP-derived payment routing characterization. The target domain schema now covers subscriptions, activation, questions, interactions, payments, answers, points, promotions, prizes, outbound messages, and processing deduplication. The relay publishes to **new** queues. Dedicated Soka MO and point-purchase payment consumers, plus guarded charge and SMS dispatchers, cover one isolated purchase path against fake providers. Other product paths and real-provider validation remain pending.

## Local commands

Use Go 1.24+ and dependencies from `go.mod`. `go run ./cmd/migrator` prints an offline migration plan without connecting to a database. For an empty, isolated MySQL 8.0+ development database, set `MIGRATION_DB_DSN` and run `go run ./cmd/migrator -apply -expected-db <exact_database_name>` after review. The command checks the target name, takes a database lock, records checksums and status, and refuses to continue after a partial failure. MySQL DDL cannot be rolled back as a transaction; inspect and repair a failed migration manually. Set `MYSQL_DSN` and an ingress policy (`INGRESS_ALLOWED_CIDRS` and/or `INGRESS_TOKEN`, or `INGRESS_AUTH_MODE=off` for local work only) and start the API with `go run ./cmd/callbacks`; every process serves metrics and health on its own loopback port (9091–9096, see `docs/operations.md`). See `docs/operations.md` and `deploy/`. Set `AMQP_URL` and start `go run ./cmd/outbox-relay`. Run `go run ./cmd/soka-mo-worker` and `go run ./cmd/soka-point-worker` with `MYSQL_DSN` and `AMQP_URL` for the isolated purchase workers. The charge and SMS dispatchers are disabled unless their respective `CHARGE_DISPATCH_ENABLED=true` or `SMS_DISPATCH_ENABLED=true` flag is set and `EXPECTED_DB` matches `MYSQL_DSN`; see `docs/charge-dispatch.md` and `docs/sms-dispatch.md` before configuring them. Never commit environment values.

`go test ./...` and `go test -race ./...` exercise the code without a database. The Go migration command applied the numbered scripts and synthetic smoke data in a disposable MySQL 8.4 container; a second run skipped applied scripts, and a mismatched database name was rejected. Invalid cross-product references, missing parents, negative payment amounts, and duplicate point awards were rejected. The callback, Soka MO, and Soka point-purchase MySQL integration tests passed in disposable isolated MySQL 8.4 databases, covering replay, amount validation, failure outcomes, and rollback. The charge and SMS dispatchers passed fake-provider tests with isolated MySQL, including no resend after uncertain responses. These tests skip during ordinary `go test` unless `TEST_MYSQL_DSN` selects a `yas_test_` database. RabbitMQ topology integration passed against an isolated broker, including confirmation, return, dead-letter, consumer disconnect redelivery, and broker restart persistence. An end-to-end relay-to-point-worker test passed against isolated MySQL and RabbitMQ, covering injected worker failure with redelivery, relay replay after broker confirmation without a second award, and dead-lettering of a malformed message; it skips unless both `TEST_MYSQL_DSN` and `TEST_AMQP_URL` are set. A crash-recovery test in `internal/e2e` repeatedly SIGKILLs the relay, MO worker, and point worker during MO-to-points traffic and passed with one financial effect per purchase and no lost callbacks. Broker or database restarts mid-run, provider contract fixtures, load tests, restore tests, and cutover rehearsal are pending.
